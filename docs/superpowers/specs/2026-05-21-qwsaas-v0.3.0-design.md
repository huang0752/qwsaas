# qwsaas v0.3.0 规划设计

日期：2026-05-21

目标版本：`v0.3.0`

当前基线：`v0.2.1`

## 背景

`qwsaas` 当前已经是一个独立的 Juhe / QW SaaS 协议层 SDK。`v0.2.1`
包含公共 `GuidRequest` 包装、WebSocket 收消息、回调解析、文本/文件发送、
部分联系人/群/标签/同步/CDN/上传下载 helper。

官方文档显示企微 SAAS 的公开接口面远大于当前 SDK，尤其是媒体消息、账号/实例、
联系人操作、群管理、标签 CRUD、私有化云存储下载等接口还没有 typed wrapper。
`v0.3.0` 的目标不是一次性追完整个官方目录，而是把常用业务闭环补齐，同时提供一个
正式通用调用入口，让未封装接口也能通过稳定公共 API 调用。

## 版本定位

`v0.3.0` 是向后兼容的 minor release。

本版本聚焦：

1. 通用调用入口。
2. 消息媒体发送与资源参数处理。
3. 账号/实例常用接口。
4. 联系人常用接口。
5. 群管理常用接口。
6. 标签 CRUD。
7. 云文件常用上传/下载接口。

本版本不改变：

- 不移除 `v0.2.x` 公开函数。
- 不改变现有函数签名和返回值形态。
- 不引入真实 Juhe 接口测试。
- 不接管 Hermes 的网关会话、mention gate、去重、权限策略、工具语义。

## 官方约束

### 调用方式

所有开放平台业务接口通过：

```text
POST https://chat-api.juhebot.com/open/GuidRequest
```

请求体结构：

```json
{
  "app_key": "...",
  "app_secret": "...",
  "path": "/msg/send_text",
  "data": {
    "guid": "...",
    "...": "..."
  }
}
```

当前 `QwSaasClient._request_public()` 已实现该结构，`v0.3.0` 要把它变成正式公共入口。

### 频率与风控

官方文档说明一分钟内调用超过 100 次会限制接口，半小时后解封，消息回调不占用。
SDK 不在 `v0.3.0` 内实现全局限流器，但文档要提示调用方自行限流；未来如有需要，
可以在上层 runtime 或 SDK optional helper 中实现。

### ID 与会话

- 微信外部联系人 ID 常见前缀：`788`
- 企微用户 ID 常见前缀：`168`
- 外部群 ID 常见前缀：`10`
- 私聊 `conversation_id`：`S:<user_id>`
- 群聊 `conversation_id`：`R:<room_id>`

SDK 不应根据前缀拒绝请求，但可提供轻量 helper 规范化或校验 `S:` / `R:` 前缀。

### 资源上传与下载

官方 FAQ 明确：

- 图片、视频、文件、小程序等资源消息的发送参数通常可以从回调里拿。
- 参数不能漏，尤其是小程序、图片、视频、文件这类结构化消息。
- `https://imunion.weixin.qq.com` 不是给开发者直接访问的下载地址。
- 资源下载需要按 `file_id` / URL 形态选择接口：
  - `https://wework.qpic.cn` 开头可以直接访问。
  - `30` 开头走 C2C 文件下载。
  - 其他 `https://` 走微信文件下载。
  - `*` 开头走大文件下载。
- 消息资源上传使用 C2C 上传。
- 朋友圈资源使用 BIG CDN。

`v0.3.0` 的媒体消息设计必须尊重这些约束：不要把复杂资源消息过度简化成少数字段，
而是支持官方字段透传，并提供从回调/上传响应构造发送 payload 的 helper。

### 消息状态

官方 FAQ 说明同一条消息可能有多条回调，例如已读、撤回等。应用可以只处理
`referid == "0"` 的原消息。`v0.3.0` 应补充模型字段和 helper，让上层更容易判断：

- `id`：用户维度下的唯一 ID。
- `seq`：用户维度下的消息序号。
- `appinfo`：全局唯一 ID，撤回和引用消息会用到。
- `referid`：为 `0` 说明原消息，不为 `0` 说明该消息是某条消息的附属变动。
- `flag`：通过枚举位判断状态。
- `asid`：微信客服消息 ID，可通过 `S:<user_id>;<asid>` 发送微信客服消息。

## 方案比较

### 方案 A：只补 typed wrappers

优点：

- 调用者发现成本低。
- 每个接口可以做参数校验和清晰测试。

缺点：

- 官方接口很多，短期无法覆盖完整目录。
- 新接口或边缘接口仍会迫使调用方使用下划线私有方法。

### 方案 B：只公开通用调用入口

优点：

- 最快覆盖所有官方接口。
- SDK 维护成本低。

缺点：

- 调用者仍要自己查文档拼字段。
- 容易漏参数，尤其是媒体消息和小程序。
- 不利于类型提示、测试和 README 示例。

### 推荐方案 C：通用入口 + 常用 typed wrappers

`v0.3.0` 采用方案 C。

原则：

- 每个官方接口都可以通过公共通用入口调用。
- 常用接口提供 typed wrapper。
- typed wrapper 尽量薄，只负责必填校验、列表清洗、默认值和 path 选择。
- 对媒体/小程序/视频等复杂 payload，优先保留官方字段，避免 SDK 猜测和删字段。

## 设计边界

### 纳入 v0.3.0

- 通用公共调用入口。
- 账号/实例常用接口。
- 媒体消息常用发送接口。
- 语音转文字查询接口。
- 联系人常用操作。
- 群管理常用操作。
- 标签 CRUD。
- 私有化云存储/C2C/BIG CDN 常用上传下载 wrapper。
- 消息/资源相关枚举和 helper。
- README、EXAMPLES、CHANGELOG、测试。

### 不纳入 v0.3.0

- 朋友圈完整能力：发布、点赞、评论、详情、删除、任务确认，放到 `v0.4.0`。
- 视频号直播、微信小店商品、合并转发等复杂业务消息，默认放到 `v0.4.0`，除非实现媒体消息时可以用通用 raw payload helper 顺手覆盖。
- 登录二维码完整流程 typed wrapper。官方文档说明原则上扫码确认后即可登录，无需调用
  `manual_login` 和 `keep_login`。`v0.3.0` 只补账号/实例常用接口和设置通知地址。
- 内部企业通讯录/组织架构私有化接口。官方 QA 说明需要购买私有化版本。

## 模块规划

### `client.py`

新增正式公共调用入口：

```python
async def request(self, path: str, data: dict[str, Any] | None = None) -> dict[str, Any]
async def request_private(self, path: str, data: dict[str, Any] | None = None) -> dict[str, Any]
```

行为：

- `request()` 走 `GuidRequest`，自动注入 `guid`。
- `request_private()` 走 `private_base_url`，不自动注入业务字段。
- 保留 `_request_public()` / `_request_private()` 作为内部实现。
- 对 `path` 和 `data` 做与当前内部方法一致的校验。
- 返回值仍是原始 normalized raw dict，不引入新的 envelope 类型。

### `enums.py`

新增 SDK 层枚举，避免上层业务到处写魔法数字。

计划枚举：

- `NotifyType`
- `QrcodeStatus`
- `MsgType`
- `MessageFlagField`
- `ContactType`
- `AddFriendSourceType`
- `BigCdnType`

设计原则：

- 使用 `IntEnum` / `IntFlag`。
- 保留官方数字值。
- 不强迫现有 callback parser 返回 enum；先提供可选转换 helper，避免破坏兼容。

## 导出策略

新增 typed wrapper 都应在 `src/qwsaas/__init__.py` 中导出。

规则：

- 用户常用函数导出到顶层。
- 内部 helper 不导出。
- 枚举导出到顶层，方便业务方写 `MsgType.TEXT` 这类判断。
- 如函数名和官方 path 不完全一致，README 中必须列出 path。

## 参数校验策略

保持 `v0.2.x` 风格：

- 必填字符串不能为空。
- 数字字段做简单非负/正数校验。
- 列表字段清理空字符串。
- 复杂 payload 只校验 dict，不删除未知字段。
- 不对业务枚举做过严限制，避免官方扩展导致 SDK 提前拒绝合法值。

媒体消息特别规则：

- SDK 不自行猜 `file_id`、`aes_key`、`md5`、`size` 等资源字段。
- 从上传响应或回调构造 payload 时保留所有官方字段。
- 对官方文档存在差异的 `file_type`，不封死默认值：
  - 必读文档写小程序封面为 `3`。
  - QA 中写小程序封面为 `1`。
  - SDK helper 接受调用方显式传入 `file_type`，README 注明差异。

## 错误处理

沿用现有异常体系：

- `QwSaasRequestError`
- `QwSaasHttpError`
- `QwSaasApiError`
- `QwSaasResponseError`
- `QwSaasPrivateObjectAccessError`

不新增业务异常，除非实现中发现现有异常无法表达资源下载的可恢复错误。
