# qwsaas v0.3.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Release `qwsaas v0.3.0` with public request entrypoints, media/file APIs, default S3-compatible storage, common account/contact/room/tag wrappers, callback helpers, docs, and tests while preserving `v0.2.x` behavior.

**Architecture:** Keep `QwSaasClient` as the thin protocol client. Add `storage.py` as the shared S3-compatible staging/presign layer, then let `file_flows.py` compose storage, `/cloud/*` private CDN wrappers, and `/msg/*` public message wrappers. Keep business wrappers thin and test them with fake HTTP clients only.

**Tech Stack:** Python 3.11, `httpx`, `aiohttp`, `boto3`, `pytest`, `pytest-asyncio`, setuptools package metadata.

---

- Modify docs: `README.md`, `EXAMPLES.md`, `CHANGELOG.md`.

## Implementation Rules

- Do not call real Juhe, real CDN, or real S3 in tests.
- Do not remove or rename existing public functions.
- Keep `QwSaasClient(app_key, app_secret, guid)` valid without storage config.
- Do not read Hermes-specific env vars in SDK core. SDK env prefix is `QWSAAS_STORAGE_*`.
- Do not leak local filesystem paths into message payloads.
- For wrappers with complex official payloads, accept `payload: Mapping[str, Any]` and preserve unknown fields.
- Commit after each task once its focused tests pass.
